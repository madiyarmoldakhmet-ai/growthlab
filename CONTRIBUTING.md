# Контрибуция в GrowthLab

Спасибо, что хотите внести вклад в проект! 🎉

Этот репозиторий публичный, и мы рады сторонним контрибьюторам. Но **финальный контроль кода всегда остаётся за владельцем проекта** — все изменения проходят ручную проверку через Pull Request (PR).

---

## ⚠️ Важно перед стартом

- **Никогда не коммитьте секреты**: `.env`, токены, `client_secret*.json`, `credentials.json`, файлы ключей `.pem` и т.д. Они уже добавлены в `.gitignore`, но проверяйте свои изменения перед PR.
- **Не делайте прямых пушей в `main`**. Ветка `main` защищена — все изменения идут только через PR.
- Обсудите крупные изменения заранее, открыв Issue с описанием того, что вы хотите сделать.

---

## 🚀 Как предложить изменение (workflow)

### 1. Сделайте fork репозитория

Откройте репозиторий на GitHub и нажмите кнопку **Fork** в правом верхнем углу. Это создаст вашу личную копию проекта.

Затем клонируйте свой fork локально:

```bash
git clone https://github.com/<ВАШ_НИК>/growthlab.git
cd growthlab
```

Добавьте оригинальный репозиторий как `upstream`, чтобы получать обновления:

```bash
git remote add upstream https://github.com/madiyarmoldakhmet-ai/growthlab.git
```

### 2. Создайте отдельную ветку под вашу задачу

Никогда не работайте в `main`. Создайте ветку с понятным названием:

```bash
git checkout -b fix/typo-in-readme
# или
git checkout -b feat/instagram-export
```

### 3. Внесите изменения и закоммитьте

Следуйте существующему стилю кода. Коммиты — небольшие и атомарные, с понятными сообщениями:

```bash
git add .
git commit -m "fix: исправил опечатку в README"
```

### 4. Отправьте ветку в свой fork

```bash
git push origin fix/typo-in-readme
```

### 5. Откройте Pull Request

На GitHub нажмите **Compare & pull request**:

- **Base repository:** `madiyarmoldakhmet-ai/growthlab` → ветка `main`
- **Head repository:** `<ВАШ_НИК>/growthlab` → ваша ветка

В описании PR укажите:
- Что и зачем вы изменили.
- Ссылку на Issue (если есть).
- Как проверить (шаги воспроизведения).

### 6. Дождитесь ревью

Все PR проверяются владельцем проекта вручную. Могут быть запрошены правки — не обескураживайтесь, это нормальный процесс.

## ✅ Требования к коду

| Чек-лист | Описание |
|----------|----------|
| Нет секретов в коде | Токены, пароли и ключи — только через `.env` (не коммитить!) |
| Понятные названия веток | `fix/...`, `feat/...`, `docs/...`, `refactor/...` |
| Атомарные коммиты | Один логический смысл = один коммит |
| Существующий стиль | Следуйте уже принятому в проекте форматированию |

---

## 🧹 Синхронизация с оригиналом

Периодически подтягивайте изменения из `main` оригинального репозитория:

```bash
git fetch upstream
git checkout main
git merge upstream/main
git push origin main
```
